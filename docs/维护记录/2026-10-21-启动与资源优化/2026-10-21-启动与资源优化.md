# 启动、内存与安装资源优化

日期：2026-10-21（北京时间）。基线提交：`e917e2a`。

## 实测结果与范围

从基线提交导出隔离的前端源码，复用同一组依赖，用相同脚本、相同合成数据比较旧实现和本次实现。未读取用户数据库，也没有执行桌面安装包构建。

环境为 macOS arm64、Node.js 22.23.1。数据包括 250 份每份 36,000 字符的需求、120 个带长消息的会话和 100 条每条保留 128K 字符输出的命令。各操作预热 3 次，测量 15 次；每次测量前主动 GC。下表为中位数，详细 P95 和原始字节数保留在机器可读记录中。

| 项目                     |        基线 |    优化后 |
| ------------------------ | ----------: | --------: |
| 文档摘要列表             |    4.822 ms |  0.363 ms |
| 会话摘要列表             |    2.398 ms |  0.101 ms |
| 命令列表                 |   75.452 ms | 16.297 ms |
| 命令列表的临时 JS 堆分配 |   50.11 MiB |  0.29 MiB |
| 启动时检查未完成命令     |    4.600 ms |  0.022 ms |
| 全局页面快照             |    7.262 ms |  0.085 ms |
| 全局页面快照序列化大小   |    79,150 B |     421 B |
| 打包清单中的运行时 PNG   | 1,123,717 B | 232,620 B |

这些数据反映指定 SQLite/API 操作、Node 模块加载与资源文件的变化。临时堆分配指一次调用前后的 JS 堆增量，包含待 GC 对象；它不等于应用常驻内存，也不是整机 RSS。全局快照的合成配置刻意很小，实际快照大小还取决于工程数、模型配置和运行状态。没有测量完整 Electron 冷启动、真实用户规模或最终 DMG / NSIS 的压缩体积。

## 启动路径

- 普通 `pnpm desktop` 的启动器只在 `--dev` 模式加载 Vite。隔离 Node 进程加载 Vite 的诊断约为 70ms、9.9 MiB GC 后 JS 堆增量；这是从本地启动器移除的依赖开销，安装后的应用原本就不执行该启动器。
- 书签与密码导入的 HTML 解析模块改为首次导入时加载。隔离加载 TestingService 的耗时从约 18.91ms 降至 12.35ms，GC 后 JS 堆增量从约 2.08 MiB 降至 1.09 MiB。该诊断不是完整桌面启动基准。
- 已删除工程的浏览器目录清理在窗口加载后进行，并在退出时等待完成。仍通过 StorageService 的操作锁排斥数据库迁移，删除标记与活动工程的区分保持不变。
- 全部工程页和客户端设置使用显式全局快照，只读取工程统计、设置及状态。进入工程后再加载文档、会话和任务摘要。已有无参数调用仍选择默认工程。

延迟非必要模块和推迟后台工作采用 Electron 的[性能建议](https://www.electronjs.org/docs/latest/tutorial/performance)。

## 数据读取与内存

本地数据库版本由 7 升至 8，事务内新增文档和会话的覆盖索引，以及命令、执行记录的状态和排序索引。项目的分析计数也从正文读取改为索引内聚合。索引只保存检索字段与摘要表达式，文档正文、分析、历史会话、命令完整输出和加密配置继续保留。

测试通过 `EXPLAIN QUERY PLAN` 确认文档/会话摘要使用覆盖索引，启动恢复使用状态索引。覆盖查询避免重复触碰大正文；表达式需与查询保持一致，依据 SQLite 的[覆盖索引说明](https://www.sqlite.org/queryplanner.html#covidx)和[表达式索引规则](https://www.sqlite.org/expridx.html)。

命令列表在 SQLite 内截取尾部、移除内部指纹，再交给 JavaScript 解析。仍遵守原来的最多 100 条记录、每条预览 500 个 UTF-16 单元、详情最多 128K 字符的规则。SQLite 按 Unicode 码点截取后，再按 JS 长度处理尾部，因此 emoji 边界和现有客户端契约一致。完整输出只在用户查看详情时读取。

工作区刷新队列合并同一轮通知，最多一个读取在途；期间出现变更会再读一次，切换工程和卸载后丢弃旧响应。测试覆盖 100 次突发刷新、在途变更、失败恢复、销毁和同步回入通知。

## 渲染与资源

- Markdown 解析器按首次实际展示加载，HTML 原文预览和空白讨论无需提前初始化 Markdown 解析依赖。
- Markdown 组件记忆化，打开网页的动作独立于网页状态上下文，普通进度或标签状态变化不再重复解析未变化的长文。
- 原文预览组件记忆化，已有 HTML 净化、无脚本/无网络沙盒和主题行为继续保留。
- 历史执行记录在展开时才创建步骤和证据节点；正在运行的记录默认展开。SSR 回归验证折叠记录不会输出长证据，运行中记录仍包含详情。
- 为窗口、Dock 和关于面板导出 512 × 512 PNG，打包清单引用该运行时图。母版与包含高分辨率资源的 ICNS / ICO 继续保留。单个打包 PNG 减少 891,097 B，约 79.3%；这不是最终安装器的节省测量。

新增刷新队列和局部加载组件使入口 JS 从 201,449 B 增至 202,062 B，总 JS 从 480,149 B 增至 481,467 B。此处以减少重复读取、解析和隐藏详情节点换取少量代码，Markdown 的解析代码仍在按需模块中。

打包继续使用已有 ASAR、最大压缩、中英文语言资源裁剪及 Word / Excel / PDF 重复构建排除配置；各导入格式及必要字体、PDF 资源和运行时依赖继续保留。


机器可读记录位于忽略目录 `artifacts/optimization-2026-10-21-round2/`：`baseline-verified.json`、`after.json` 和 `comparison.json`。隔离基线源码和中间测量记录在复测完成后清理。
