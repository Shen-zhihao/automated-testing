# 资源、安装内容与内存优化

## 本次结果

以相同 Electron 44.9.1、macOS arm64、未签名 `--dir` 构建进行前后对比。测量的是应用目录，不是 DMG / NSIS 下载文件；实际安装包压缩率、签名和其他架构的体积需在正式出包时验证。

| 项目 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 应用目录磁盘占用（`du -sk`，MiB） | 414.33 | 307.70 |
| 应用文件总字节数折算（MiB，不重复计符号链接） | 384.52 | 289.01 |
| `app.asar`（MiB） | 69.47 | 20.33 |
| UI 入口 JS（KiB） | 425.48 | 181.85 |

磁盘占用减少 **106.63 MiB，约 25.7%**。UI 页面拆成按需加载的模块，入口文件体积不等于首个文档页面的全部加载量，Markdown 和文档预览仍会加载各自依赖。

## 资源与代码整理

- 安装内容排除依赖中的源码映射、测试、示例和开发文档；保留许可证文件。
- ExcelJS 使用 Node 实现，去掉重复的浏览器 `dist`。Mammoth 去掉浏览器 bundle。PDF.js 只保留当前使用的 legacy 解析实现及必要的 worker、字体、CMap、WASM、ICC 与原生 Canvas 依赖。
- Electron 保留简体中文、繁体中文、英文及对应语言变体。兼容 macOS 下划线命名与 Windows 连字符命名，避免裁剪掉系统对话框所需的中文资源。
- 打包配置使用最大压缩；不裁剪 Chromium 运行能力，不另带第二套浏览器。
- 删除 10 个已无入口引用的旧演示文件：演示状态客户端及测试、`usePrototype`、旧任务辅助函数、旧布局类型、旧技能选择组件及样式、3 份旧任务页面样式。
- 技能模板改为静态数据，移除模拟任务与聊天状态逻辑；各业务页面和技能弹窗按需加载。Less 移到开发依赖。
- 启用 TypeScript 未使用变量和参数检查，防止废弃引用继续积累。

工程中没有需要重压缩的大型自有图片、视频或字体素材，主要节省来自依赖构建副本和多余语言资源。

## 内存与刷新策略

1. 抽离轻量文档格式常量和文本校验函数。主进程的飞书与 IPC 模块不再连带加载 Word / Excel 解析库；解析 Worker 按文件格式加载对应依赖，完成或失败后退出。
2. 工作区列表直接查询 SQLite 摘要，不再把全部聊天消息、需求正文、报告和历史记录解析成 JavaScript 对象。需求变更检测在 SQL 中比较，聊天只读取最近三次执行的摘要。
3. 网页事件使用独立通知通道，不触发整个工作区重新读取；去掉每 800 毫秒轮询，主进程对同类通知在 32 毫秒内合并。
4. 网页尺寸未变化时不重复设置原生视图边界，不反复移除、添加同一视图；弹窗观察只关注 body 的直接子节点，避免监听整个聊天和文档 DOM。
5. 已关闭网页空闲超过 5 分钟后回收。已关闭网页超过 6 个时优先回收较早关闭的空闲页。运行中的任务、填入密码中的页面和仍有子网页的 opener 受保护。打开的标签不自动回收。
6. 再次打开已回收的任务页会重新加载网址，持久 Cookie、本地网站存储和导入的加密密码仍保留。未提交表单、滚动位置等页面临时状态可能重置。已审阅计划在需要时可后台重建网页，从计划起始页执行。
7. 自动化运行期间禁用后台节流，结束后恢复；关闭标签不取消任务，退出应用时取消任务并清理回收定时器和待发通知。

一次独立 Node 进程的诊断中，导入飞书模块产生的 GC 后 JS 堆增量从约 **13.86 MiB** 降到 **0.24 MiB**，不再加载 ExcelJS。此数据用于确认依赖隔离，**不代表完整 Electron 应用的内存或启动耗时基准**。

- `make frontend-check`：类型检查、格式检查和 **82 项桌面端测试**通过。
- `make frontend-build`：共享包和 UI 生产构建通过。
- 新增回归覆盖：关闭页超时回收、数量上限、重新打开、运行任务保护、密码填入保护、opener 保护、回收后后台重建任务页、摘要读取不加载完整数据。
- 直接使用裁剪后的 Electron 可执行文件与 `app.asar` 运行 Worker，MD、TXT、CSV、HTML、PDF、DOCX、XLSX、PPTX 的导入检查通过；检查格式预览及本地 UI 入口存在。
- 核对安装内容：重复构建和 `.map` 均未进入 `app.asar`，保留所需解析入口、PDF worker、macOS arm64 Canvas 二进制和 219 个依赖许可证文件；中英文语言文件存在。
- `git diff --check` 通过。开发环境已重新启动。

本次只在 macOS arm64 检查应用目录和包内运行时；没有生成正式安装器，也没有验证 Windows / Intel Mac 安装运行。电脑处于锁屏状态，新增内存策略的原生界面点击验收尚未完成；后台任务保护由回归测试验证。

## 复查命令与产物

日常检查从项目根目录执行：

```sh
make frontend-check
make frontend-build
```

已有应用目录可使用以下命令验证精简后的依赖与语言资源。参数使用 `.app` 或 Windows `.exe` 的绝对路径；该命令只生成临时测试文档，不读取用户资料。

```sh
cd frontend
pnpm --filter test-agent-desktop check:package /绝对路径/自动化测试助手.app
```

本次机器可读指标及日志保留在忽略目录 `artifacts/optimization/`：`size-comparison.json`、`import-before.json`、`import-after.json`、`package-audit.json` 和各检查日志。体积对比用的两份大应用目录与 UI 基线副本在验证完成后清除。用户数据库、浏览器资料与其他原有产物未清理。
