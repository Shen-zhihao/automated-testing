# 进程与长对话资源优化

日期：2026-10-22，北京时间。本轮在已有资源优化与对话上下文管理基础上继续处理列表读取、长对话渲染和首屏加载。

## 实测结果

SQLite 基准使用同一份合成数据：250 份每份 36,000 字符的文档、120 个会话、100 个各含 100 条用例的任务，以及 100 条各保留 128K 字符输出的命令。预热 3 次、测量 15 次，取中位数。

真实 Electron 基准使用 macOS arm64、仓库中的 Electron 运行时和生产 UI，在临时目录建立隔离资料库。空工程和 400 条消息的长对话各运行 3 次，取中位数；不读取用户数据库、凭据或浏览器资料。窗口保持隐藏，不打断当前工作。

| 项目 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 命令列表读取 | 16.052 ms | 0.300 ms |
| 测试任务列表读取 | 4.623 ms | 0.266 ms |
| 400 条对话初始消息元素数 | 400 | 40 |
| 长对话场景渲染进程工作集 | 327.88 MiB | 174.30 MiB |
| 长对话场景各进程工作集汇总 | 654.33 MiB | 501.05 MiB |
| 空工程各进程工作集汇总 | 459.73 MiB | 459.27 MiB |
| UI 入口 JS | 203,653 B | 191,028 B |
| 首窗加载，主脚本开始至 did-finish-load | 503.82 ms | 485.44 ms |

长对话场景工作集汇总减少约 23.4%，渲染进程工作集减少约 46.8%。工作集汇总可能重复计算共享页，不等于唯一物理内存或整机 RSS。空工程基础占用基本不变；Electron 的浏览器、GPU、网络及渲染进程继续保留。

首窗测量排除了 pnpm 构建、运行时准备和 Electron 引导脚本执行前的开销。3 次小样本仍受系统缓存和调度影响，本次不以约 18 ms 的差值宣称稳定的整机冷启动提速。实际改善主要来自更少的首屏依赖，以及较长对话不再一次性创建全部节点。

## 列表读取

数据库从版本 9 升至 10，在事务中建立命令预览、任务摘要与需求快照标题的覆盖索引。命令预览的 JSON 截取与指纹移除在写入索引时完成，列表查询不再逐条处理完整的 128K 日志。任务列表也直接读取索引内的标题、范围、用例数量、版本状态和关联需求名称。

原文、完整命令输出、历史任务、分析检查点及加密配置继续保留。摘要索引随写入自动更新，代价是少量额外索引空间及写入计算，换取高频列表查询减少大 JSON 读取。迁移、WAL 备份、目录指针及工程隔离机制继续使用原有实现。

## 对话渲染与后台资源

- 长对话初次打开显示最近 40 条消息，每次可展开更早的 40 条，并调整滚动位置。完整消息仍保存在本机并参与上下文选择，未删除历史记录。
- 消息使用浏览器的离屏内容渲染优化，减少可视区之外的布局与绘制。
- 打字动画从反复复制字符数组改为按完整 Unicode 字符边界切片；长回复降低刷新频率，最长动画从 16 秒缩至 12 秒。32K 字符回复的调度上限约从 356 次降至 67 次，这不是 CPU 降幅测量。
- 窗口不可见或切到内置网页时结束打字动画，保留完整回复，避免后台持续解析增长中的 Markdown。
- 已关闭网页的空闲保留时间从 5 分钟缩至 2 分钟，保留上限从 6 个缩至 2 个。仍保护运行中的任务、下载、密码填入和有活动子页的原网页；打开的标签不会自动回收。持久 Cookie 和网站本地存储继续保留，已回收页面重新打开时临时表单或滚动位置可能重置。

## 首屏资源与安装内容

内置浏览器控件、工程弹窗和文档目录按实际使用加载。入口 JS 减少 12,625 B，约 6.2%。增加消息渐进渲染和按需模块后，所有 JS 文件总量从 493,725 B 变为 496,433 B，增加 2,708 B，约 0.55%；首屏减少不代表全部代码或安装器同幅减少。

保留已有 ASAR、最大压缩、语言筛选与重复依赖构建排除配置。本轮没有构建 DMG、NSIS 或其他安装包，也没有裁剪文件解析格式、字体、PDF 支持文件或系统凭据身份。

- `make frontend-check`：类型、格式检查及 196 项测试通过。
- `make frontend-build`：共享包与 UI 生产构建通过。
- 覆盖 v1 / v5 / v7 / v9 升级、完整日志和任务保留、摘要自动更新、SQLite 完整性、WAL 与保存目录迁移、网页回收及运行任务保护。
- SSR 验证 400 条消息只初始渲染 40 条，较早消息仍在源数据中；Unicode 与长回复刷新上限回归通过。
- 真实 Electron 隔离检查确认初始 40 条、展开后 80 条及消息顺序正确；按需新建工程弹窗、取消操作和空白内置浏览器控件可正常打开。未连接模型或外部网站。
- `git diff --check` 通过。Windows、Intel Mac、正常可见窗口的完整交互负载与最终安装包尚未实测。

机器可读结果位于忽略目录 `artifacts/performance/2026-10-22-resource-optimization/`，包括 `before.json`、`after.json`、`comparison.json`、`electron-baseline-check.json`、`electron-after.json`、`electron-chat-before.json` 和 `electron-chat-after.json`。临时 Electron 用户资料目录在每次测量结束后清理。

从项目根目录执行：

```sh
make frontend-check
make frontend-build
node --expose-gc frontend/apps/desktop/scripts/benchmark-resources.mjs artifacts/performance/recheck.json
node frontend/apps/desktop/scripts/benchmark-startup.mjs artifacts/performance/startup.json recheck
node frontend/apps/desktop/scripts/benchmark-startup.mjs artifacts/performance/chat.json recheck chat
```

启动基准会启动三次隔离的隐藏 Electron 实例，需要可运行桌面应用的 macOS 或 Windows 环境；应避免同时运行多个性能基准，以减少相互干扰。
