# 文档分析与模型设置

日期：2026-10-20（北京时间）

## 开始使用

在 `frontend` 目录运行 `pnpm desktop`，进入「设置」填写模型服务地址、模型名称和 API Key，点击「保存并测试连接」。本机免鉴权模型可以不填写 Key。测试连接仅发送一条简短消息，不发送任何文档。

默认支持 OpenAI 兼容的 Chat Completions；服务要求新版接口时选择 Responses。地址填写 API 根地址，例如 `https://api.openai.com/v1` 或 `http://localhost:11434/v1`，不要包含密钥。远程服务要求 HTTPS，本机 localhost / 127.0.0.1 / ::1 可使用 HTTP。

API Key 和 App Secret 已保存时显示固定 `********`，不回显密钥或真实长度；输入留空保留已有值。最大输出 Token 使用下拉选择，包含 512、1K、2K、4K、8K、16K、32K、64K、128K、256K 和 384K。该值限制单次回复长度，并非上下文容量；可用上限由服务商与具体模型决定，应用不会自动增大已保存的设置。以 2026-10-20 的 [DeepSeek 官方接口说明](https://api-docs.deepseek.com/api/create-chat-completion/)为例，Flash 的输出上限是 393216（384K），不能把 1M 上下文直接填成输出上限。

输出 Token 参数默认 `max_tokens`，某些新版 OpenAI 模型要求 `max_completion_tokens`；Responses 使用 `max_output_tokens`。温度可留空，此时不发送该参数。需求分析按功能与章节分步生成，单次正文截断时自动续写，不需要为整份报告设置一个超大输出额度。输出上限也可能包含模型推理消耗；若额度用完但没有正文，会明确提示提高单次额度后继续。生成前的范围检查同样遵守已配置的输出额度，不再单独限制为 1024 Token。

DeepSeek 官方接口默认开启高强度思考，可能在输出正文前耗尽小额输出预算。对 `api.deepseek.com` 的 `deepseek-flash` 和 `deepseek-v4-pro`，文档分析（含范围检查、分段阅读、实现步骤、验收与续写）及连接测试使用非思考模式：Chat Completions 发送 `thinking.type=disabled`，Responses 发送 `reasoning.effort=none`，仍保持用户保存的输出额度。其他模型服务沿用原请求参数，普通工程对话也不强制切换模式。开关依据见 [DeepSeek 官方思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)。

API Key 经 Electron safeStorage 加密后保存，不回显给界面。留空保留已保存的 Key；勾选「清除」后保存可移除。修改服务地址会清除旧 Key，需重新填写，避免把旧服务的密钥发送给另一服务。密钥解密失败会提示重新配置，不回退明文保存。

## 本地文档

在「文档分析」点击「导入本地文档」，通过系统文件选择器选择文件。每次最多 10 份，每份最多 20 MB，提取后最多 20 万字符。单份失败不会丢弃其他成功导入的文件；超过限制会报错，不静默截断。

| 格式 | 提取范围 |
| --- | --- |
| TXT / MD / Markdown | 文字；支持 UTF-8、UTF-16 BOM、GB18030 解码，Markdown 另提供格式预览 |
| CSV / TSV | 原始文本与表格预览，保留带引号单元格内的换行 |
| JSON | 原始文本 |
| HTML / HTM | 正文、控件约束、事件绑定、条件分支与内联逻辑；支持含 `__bundler/template` 的单文件原型；静态结构预览，不执行脚本或加载外链 |
| PDF | 文字层、页码，最多 300 页；扫描页提示未 OCR |
| DOCX | 正文文字与格式预览，保留可识别的标题、列表、强调、表格、合并单元格与内嵌常见图片；不保证 Word 分页和浮动布局完全一致 |
| XLSX | 工作表名、行号、单元格文字与表格预览，保留合并单元格；最多 5 万单元格，不重算公式 |
| PPTX | 按演示顺序提取幻灯片文字，最多 500 页 |

旧版 DOC / XLS / PPT 请先另存为新格式。DOCX 可预览内嵌常见图片，但不识别图片文字；图表、附件和受密码保护的文件暂不解析。模型仅接收提取的文字。Office 文档解压后上限 100 MB；复杂文档解析超过 60 秒会停止。导入后先查看「提取原文」核对内容，原始文件不会改动。

### HTML 原型分析

“页面文字”以页面、弹窗为单位分组，可点击标题展开。预览保留标题、段落、纵向排列、行内分组、表格、强调和删除线，输入区域与操作入口分别显示；动态绑定以可读占位标签展示，隐藏或条件内容单独收起，控件与源码放在“提取细节”中按需查看。此调整只改变预览，分析原文完整保留。已导入原型可点击“重新提取格式”应用新排版，文字未变化时保留已有分析。

普通 HTML 和含 `__bundler/template` 的单文件原型均可导入。此类打包文件先读取 JSON 内嵌页面，再提取正文、表单字段与校验属性、事件绑定、页面/条件分支及内联脚本。只读取数据，不执行脚本、不加载外链，不把字体、图片或打包加载器当作业务文字。格式预览显示提取结构；需要操作原型时仍应使用原文件。

外部运行时生成的内容、其他打包页面可能未覆盖，会在提示和模型材料中标明。内嵌模板最多 8 MB、最多解包3层；内联脚本单个最多6.4万字符、合计12万字符，超限脚本整段跳过并明确提示。最终提取仍受20万字符上限约束，不截断后冒充完整。依赖外部应用脚本的纯SPA或多页原型，应补充业务源码或逐页导出。

HTML 分析除功能清单、实现步骤与验收标准外，还必须包含“端到端业务流程”“关键交互与状态流转”“错误处理与恢复”“测试实施方向”。每段阅读与生成均保留入口、动作、条件、状态、跨页数据、错误及恢复证据；测试方向写明场景、前置数据、操作、断言、测试层级和所需环境。报告区分原型可验证的交互、建议自动化的规则、需要真实接口或App验证的上传/下载/扣费/持久化等能力；演示数据、定时器、模拟审核和成功提示不会作为真实实现依据。四个额外章节分别按原文分段生成后组装，截断时自动续写。缺少关键章节时不覆盖已有结果；应用不会自动修改输出额度设置。

## 飞书：应用身份读取（Windows / macOS）

应用直接调用飞书官方接口，以企业自建应用身份读取文档，不需要安装 Codex、连接器、Python 或额外 Node.js。设置界面只有 App ID、App Secret 和「测试连接」，不使用个人账号登录或回调地址。

### 首次配置

1. 在[飞书开发者后台](https://open.feishu.cn/app)创建企业自建应用，在「凭证与基础信息」获取 App ID 和 App Secret。
2. 在权限管理中开通以下**应用身份**权限，并完成发布和管理员审批：
   - `docx:document:readonly`：读取新版文档；
   - `wiki:wiki:readonly`：解析知识库链接。
   - 如需预览文档内嵌图片，还需开通[下载素材接口](https://open.feishu.cn/document/server-docs/docs/drive-v1/media/download)要求的应用身份只读权限，并确认目标文档允许应用下载素材。
3. 为应用授予目标文档的阅读权限。在飞书文档右上角「… → …更多 → 添加应用」中选择该应用；知识库文档还需要为应用授予对应知识库的访问权限。接口权限与文档访问权限是两项不同的授权，你本人能打开文档不代表应用能读取。参考[飞书权限错误说明](https://open.feishu.cn/document/server-docs/api-call-guide/generic-error-code)。
4. 在 App「设置 → 飞书应用」填写 App ID、App Secret，点击「测试连接」。测试成功后自动加密保存凭据；已有配置的 App Secret 留空时保留，更换 App ID 时必须填写对应的新密钥。
5. 返回「文档分析」，导入 `feishu.cn/docx/…` 或 `feishu.cn/wiki/…` 链接。无需配置重定向 URL、开放本机端口或进行浏览器授权。

测试连接只验证应用凭据是否能换取应用访问令牌，不能验证任意文档是否可读。具体文档权限会在导入时检查；缺少接口权限时提示开通并发布应用身份权限，缺少文档权限时提示为应用授予阅读权限。

### 凭据与读取范围

App Secret 经系统安全存储加密，只保存在当前用户的数据目录，不回显，不写入代码或安装包。应用访问令牌仅保存在主进程内存中，关闭 App 后清除。重启或到期后自动使用已保存的应用凭据获取新令牌，多个并发请求共享一次获取。读取遇到令牌失效时仅自动重新获取并重试一次，避免无限重试。

测试失败、系统加密失败或操作取消时保留此前配置。更换配置后，尚未完成的旧请求不能恢复旧凭据。升级会保留已经填写的 App ID 和加密 App Secret，移除旧的用户令牌、续期信息、回调端口和连接器路径；已导入文档、分析结果及模型配置继续保留。

文档文字通过官方纯文本接口读取，同时分页读取文档块还原标题、段落、列表、代码、表格和合并单元格；知识库先解析到新版文档。内嵌图片通过官方素材只读接口下载，PNG、JPEG、GIF、WebP 以本机内嵌数据随预览保存到 SQLite，重启后无需重新下载；下载不跟随重定向，访问令牌不进入预览或渲染进程。相同图片在一次提取中只下载一次；最多读取 60 张不同图片，单张最多 4 MB、合计最多 5 MB，图片读取阶段最长 60 秒。图片不可访问、格式不支持或超出上限时，在原位置和文档提示中说明原因，仍保留正文及其余可读取图片；附件、内嵌多维表格和画板仍以占位说明显示。图片仅用于预览，不识别图片内文字，也不发送给分析模型。格式获取失败时明确提示，并保留完整纯文字。当前支持飞书中国版链接；Lark 国际版或其他云文档请先导出为本地文件。

工程文档收纳在左侧「需求分析」下的可折叠列表，点击文档名称即可切换，不再单独占用正文区域，也不设置文档搜索框。导入默认提取格式，「提取原文」直接显示格式预览，不再提供纯文字切换。Markdown 保留标题和表格；HTML 净化后展示；CSV/TSV/XLSX 显示表格结构。外部预览禁用脚本、链接跳转和网络请求；PDF、PPTX 目前仍按页保留文字，尚未还原原始页面布局。格式预览最多 8 MB，超出时明确提示并保留完整提取文字。

DOCX 预览以内容顺序、标题层级、列表嵌套、表格行列和合并关系清楚可读为目标，不要求字体、行距和分页与 Word 一致。宽表格可独立左右滚动，内嵌图片按比例适应可用宽度；无法读取、不支持或超出大小限制的图片显示位置说明并提示，不留无说明的空白。旧文档可重新提取以应用新的标题和图片处理规则。

早期导入的文档只有纯文字，或飞书预览仍显示图片占位时，可点击「重新提取格式」，需要原文件仍在或飞书链接仍可读取。重新提取失败不会覆盖已有文档；文字未变化时保留分析，文字变化时清除旧分析并提示重新分析。仅补读图片和更新预览不会使已有文字分析失效。

根据[获取应用访问凭证文档](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/authentication-management/access-token/tenant_access_token)，令牌端点为 `https://accounts.feishu.cn/oauth/v3/token`，使用 `client_credentials`。文档接口令牌只发送到固定的飞书官方域名。使用 API 的联网需求仅涉及飞书及你选择的模型服务，本地数据仍使用 SQLite，无 Docker 或远程数据库。

已在 macOS 桌面 App 验证真实应用凭据的连接测试，以及以应用身份导入已授权的新版文档。Windows 使用同一套流程，尚未进行实机或安装包验证。

## 分析与数据保存

选择原需求文档，填写可选的「补充要求」，点击「生成实施与验收文档」。界面会显示当前模型和发送地址。模型接收提取后的文字，不接收原始二进制文件或未下载的附件。

原文按最多约 6000 字符分段，逐段提取功能、实施依赖、验收规则与原文引用。所有分段都参与，完整保留每段证据；仅合并完全同名的功能，语义相似但名称不同的条目保留供核对。随后分别编写每个功能的实现步骤和验收标准，最后由本机组装 Markdown，不再让模型一次写完整份报告，也不反复压缩全文笔记。每次请求仅携带当前功能的证据、范围约束与必要编号，使用字符预算限制输入，不把字符数冒充精确的 Token 数。

单步收到输出额度截断时保存正文，并自动从末尾续写；校验衔接内容后再拼接，保留 Markdown 空格和换行。每次运行的单步最多发起 12 次生成请求（包含续写和纠错），仍未完成时保留进度并提示继续，避免无限请求。模型正文中的小标题统一收纳到功能标题之下，代码示例保持原样，不因标题层级差异拒收整段。结构、编号或验收步骤关联未通过校验时，附上具体错误，最多自动重写当前步骤两次；其他已完成步骤继续复用。纠错反馈保存在草稿中，重启后可继续修正。未返回正文、拒答、服务错误或纠错后仍不合格的内容不会冒充成功。

界面在「已生成内容」中逐段展示范围、功能步骤和验收内容，不必等待全部生成。可选择已生成的功能阅读，点击「查看最新内容」跳到最新段落；生成期间勾选「新内容生成时自动切换」后，后续内容生成时会自动切换到对应功能。手动选择某个功能会取消自动切换，保留阅读位置。可以复制当前版本的全部已生成内容，复制内容明确标为未完成草稿。已生成、续写中、正在修正的段落分开标识，草稿不作为完整报告创建测试任务。上次成功的完整报告仍可单独展开查看。

生成中「补充要求」始终可编辑，点击「应用补充要求」才向模型提交，单纯输入不触发联网。应用后停止旧请求，按新的完整要求开始新版生成，上一版草稿保留供查看并标明「待按新要求更新」，避免把旧要求下的内容当成最新结果。旧版和新版可切换，最多保留一版先前草稿；完整报告成功保存后清除过程草稿。新请求仍占用分析、存储和工程操作锁，完成或停止前不能迁移数据或清理工程。

生成过程与最近一次成功结果分开保存在本机 SQLite，失败、取消和关闭后已完成步骤及已返回的截断正文仍保留并可展示；已发送但尚未收到的内容不能恢复。重新打开同一文档，保持补充要求、模型和服务等配置不变，点击「继续生成文档」即可恢复；调整单次输出额度或超时仍可接着生成。更换原文、补充要求、模型、服务地址、接口格式、输出参数类型或温度会开始新的草稿。仅更新格式预览且文字未变化时保留草稿。续写无法衔接或没有新增内容时，按同一纠错次数上限完整重写当前段，其他已完成段落保留。全部生成并通过校验后才替换成功报告，同时清除本次草稿。

结果为一份 Markdown 文档，包括需求范围与功能清单、功能实现步骤、功能验收标准、实施顺序与依赖、待确认问题。功能使用 F 编号，实现步骤使用 S 编号，验收标准使用 AC 编号相互关联。每条验收标准要求写明前置条件、操作或输入、可观察的预期结果、原文依据与待验收状态。原文未定义的实现方案标为建议，缺失规则列为待确认，不擅自确定阈值、优先级或工期。模型只处理资料，不调用飞书写入接口或执行测试；仍需结合原文核对生成内容。

生成成功后在「实施与验收」页签查看，可切换「预览」和「Markdown 源码」，也可复制 Markdown。点击「保存为 .md」打开系统保存对话框，选择文件名与位置；保存完成会显示完整地址。导出的 UTF-8 文件与当前预览的 Markdown 内容一致，包含需求来源、生成时间和模型信息。取消保存不会创建文件，保存失败可重试，禁止覆盖原需求文件。历史分析仍可预览和导出，重新生成成功后更新为新的实施与验收格式。

文档文字、最近一次成功分析和配置存放于 `app.getPath('userData')/storage/test-agent.sqlite`，重启保留。普通模式目录为 Test Agent，开发模式为 Test Agent Development。删除文档只移除应用内副本和分析，不删除源文件或飞书文档。对话、任务、需求快照及执行记录也保存在同一数据库；文档删除不会破坏已有任务中的需求依据。分析结果可以从「在工作台讨论」或「创建测试任务」继续处理，详见 [测试任务与内置浏览器](../2026-10-20-测试任务与内置浏览器/2026-10-20-测试任务与内置浏览器.md)。

默认 macOS 路径为 `~/Library/Application Support/Test Agent/storage/test-agent.sqlite`，开发模式为 `~/Library/Application Support/Test Agent Development/storage/test-agent.sqlite`；Windows 对应 `%APPDATA%\\Test Agent\\storage\\test-agent.sqlite`，开发模式目录名为 `Test Agent Development`。设置页始终展示本次运行实际使用的完整目录和数据文件地址，并可点击「打开目录」。

在「设置 → 本地数据 → 选择保存目录」选择目录，点击「保存并迁移」后立即生效，后续导入也保存到新目录的 `test-agent.sqlite`。文档文字、格式预览、分析结果与加密配置一起迁移，源文件不移动；旧目录保留迁移时的副本，之后不再更新。目标已有同名数据库或日志文件时拒绝覆盖；导入、分析或保存配置期间不能迁移。迁移失败继续使用原目录。目录指针存于原用户目录的 `storage-location.json`，系统加密身份保持不变。自定义目录失效或外接磁盘离线时会提示恢复原路径，不自动创建空库。

## 验证方式

执行 `pnpm typecheck`、`pnpm format:check`、`pnpm test`、`pnpm build`。测试使用生成的小型文档和本机 HTTP 服务，覆盖格式提取、重开数据库、密钥不回显、模型参数、请求错误、分段覆盖、取消和重试；飞书覆盖应用凭据验证、旧配置迁移、密钥加密与脱敏、文档和知识库读取、令牌缓存与并发更新、权限错误、失败保留旧配置以及关闭或变更配置时的并发状态。实际模型质量与供应商兼容性仍需用户填写自己的服务配置后验证。

参考接口：[OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、[Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)、[飞书文档纯文本接口](https://open.feishu.cn/document/server-docs/docs/docs/docx-v1/document/raw_content)。
