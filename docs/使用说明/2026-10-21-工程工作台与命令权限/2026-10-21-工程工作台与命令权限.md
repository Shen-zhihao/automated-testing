# 工程工作台与命令权限

每个工程保存自己的需求、分析、对话、测试验收和命令记录。左侧切换工程，右侧处理工程内部工作。旧版本的数据升级后进入“默认工程”，不会清空。

## 工程入口

| 入口       | 用途                                                                             |
| ---------- | -------------------------------------------------------------------------------- |
| 工程概览   | 查看资料数量、讨论、验收任务和需要关注的执行结果                                 |
| 需求分析   | 导入本地文档、HTML 原型或飞书文档；保留结构预览，生成实施与验收 Markdown         |
| 对话管理   | 直接提问，按需从附件图标引用需求原文和分析；保留结论，后台执行工程命令并查看结果 |
| 测试验收   | 从需求或对话建立任务，生成测试文档，审阅网页计划并执行，按状态筛选               |
| 文件与缓存 | 清理需求与关联记录、导出文件、命令目录、浏览器缓存，或删除整个工程               |

工程名称和说明可随时修改。切换工程不会停止已有分析、测试或命令。网页在当前工程的顶部标签中打开；关闭标签继续遵循原有后台任务规则。

左侧顶部的按钮可以收起或展开导航，选择会保存在本机，刷新和重启后保留。收起后保留工程首字图标、当前工程功能、新建工程、技能模板和客户端设置，悬停可查看完整名称。

右击左侧任意工程，选择“删除工程”，输入该工程的完整名称后确认。键盘聚焦工程后可按 Shift+F10 打开菜单，Esc 关闭。删除其他工程时保留当前页面；删除当前工程后返回全部工程。确认框与“文件与缓存”页面共用删除流程，文件、缓存清理规则一致；运行中的任务或受保护的导出文件仍会阻止删除并显示原因。

模型、飞书应用配置、书签和加密密码库属于客户端全局设置。网站 Cookie、登录状态与缓存按工程隔离；默认工程沿用旧浏览器分区，以保留升级前的网站登录状态。

## 外观模式

外观统一在“客户端设置 → 外观”中配置，侧边栏不再放置独立的外观选择器：

- 跟随系统：默认模式，随 Windows/macOS 的浅色、深色变化立即切换。
- 浅色：始终使用浅色外观。
- 深色：始终使用深色外观。

选择后立即生效并自动保存，重启保留。外观属于整个客户端，各工程共用，不影响工程数据。窗口、菜单与原生控件由 Electron 主题同步；工程页面、对话、测试、弹窗、书签/密码管理、命令输出及文档预览使用同一套主题色。原生文档预览随颜色通知变化，无需重载文档，保留滚动位置和展开状态。

配色参考 VS Code 官方 [Dark Modern](https://github.com/microsoft/vscode/blob/main/extensions/theme-defaults/themes/dark_modern.json) 和 [Light Modern](https://github.com/microsoft/vscode/blob/main/extensions/theme-defaults/themes/light_modern.json)，使用中性灰分层。深色进一步加深为黑灰：主背景 `#141414`、标题栏与侧栏 `#101010`、卡片 `#1c1c1c`；浅色使用白色内容区和 `#f8f8f8` 的标题栏、侧栏。蓝色只用于操作与选中状态，状态提示保留语义颜色。

窗口最上方的标题栏与整个界面一起切换颜色，可拖动移动窗口。按照 [Electron 官方标题栏方案](https://www.electronjs.org/docs/latest/tutorial/custom-title-bar)，macOS 保留原生红黄绿按钮，Windows 保留原生最小化、最大化、关闭按钮，并同步按钮区域的背景和图标颜色。窗口控制区域预留空间，标题文字不会覆盖按钮。外观选择仍统一放在客户端设置中。

内置浏览器会向网站提供当前颜色偏好；网站实际显示效果取决于网站自身是否提供深色样式，应用不会反色图片或修改网站内容。

外观设置单独存入 SQLite 的 `appearance` 配置，不修改模型或加密凭据；保存失败时保留此前的主题。启动时在窗口加载前恢复原生主题，降低深色启动时的白屏闪烁。

外观新增检查包含模式切换与跟随系统、重启持久化、不覆盖原有配置、失败保持原状态、监听器清理、中性灰底色、两套配色的变量完整性和主要文字对比度，以及 Windows 按钮配色更新和 macOS 平台 API 边界。macOS 已在隔离客户端验证深浅色切换、顶部标题栏同步、设置页入口和原生窗口缩放；未切换真实操作系统外观，Windows 未做实机验证。

## 命令执行

命令执行是对话中的后台工具，不设置固定页面、工具窗口或权限下拉框。在对话中要求运行本工程已有的检查、构建或测试命令，通过范围与安全检查后自动排队执行，不额外弹出终端。所需脚本、配置和依赖放在“文件与缓存”显示的工程工作目录中。

- 模型提出的命令与当前用户请求一起接受检查，通过后在后台执行。同一工程串行，最多同时运行三个工程。
- 执行结束后，真实状态、退出码、输出和错误交给模型整理，再呈现最终回复；不会把候选命令当作已经执行成功。
- 回复下方可展开“后台执行记录”查看明细。点击“停止回答”会停止当前命令，并取消同工程的剩余队列；关闭应用也会终止执行。
- 排队命令在执行前重新检查脚本和配置，文件变化后阻止执行。已完成的命令不能重复启动，需要重新发起请求。
- 升级或重启时，旧待确认、排队和未完成记录标记为中断，不自动补跑。旧权限配置不再影响新的后台请求。
- 单条命令最多运行 120 秒，保留末尾 128K 字符输出；界面标明截断。退出码非零、停止、超时、启动失败、应用中断分别记录，不把未执行的命令标为成功。
- 命令列表展示最近 100 条，完整历史保存在本机，随工程清理。对话可读取本对话最近几条命令的状态与部分输出继续分析，不自动发送整个日志。

macOS 使用系统账号的默认 Shell，Windows 使用 `ComSpec` 指定的系统命令解释器（通常为 `cmd.exe`）。输出显示在工程界面，不额外弹出终端窗口。工具需要本机已安装并可通过客户端进程的 PATH 找到；桌面应用的基础功能仍不依赖用户额外安装 Node/Python。

支持工程内读取、已有脚本、构建与测试工具，例如 `ls`、`rg`、`git status`、`pnpm test`、`node tests/check.mjs`。不开放提权、命令串联、管道、重定向、内联代码、任意下载执行与工程外路径参数。Git 仅允许状态、差异和历史读取。脚本和包配置会参与审查，审查失败、超时或格式不合法时不执行。

本工具运行当前账号的本地 Shell，限制命令范围、工程相对路径、可用工具和运行时间。**工作目录和规则检查不等于系统级沙箱**；工程脚本和依赖仍使用系统账号权限，应使用可信的脚本和依赖。没有 Docker，也不依赖 Codex 或连接器。

## 智能体范围

智能体固定服务于当前工程的需求分析、功能实施拆分、测试设计、执行、缺陷分析与验收。无关问题会引导回工程；要求忽略规则、伪装授权、读取系统凭据或执行危险操作会拒绝。

对话在回答前审查请求，生成后再审查候选回答。文档与测试文档生成也检查请求范围。文档、网页、附件、历史回复及命令输出均作为非可信资料，不能授予权限。拒绝的回答不能保留为测试依据。模型返回的普通 Markdown 不会被当作命令执行；结构化候选也必须通过主进程的范围检查，再由后台执行器处理。

这些是应用策略、确定性校验与模型审查的组合，不声称能够保证任何模型、任意第三方脚本和依赖绝对不可绕过。模型接口不可用时，审查关闭放行通道；已有资料和报告保持不变。

## 文件清理和删除

需求和分析仍存放在设置中显示的 SQLite 数据库内；工程命令工作目录位于固定客户端数据目录的 `projects/<工程标识摘要>/`，具体地址在“文件与缓存”中显示。更换 SQLite 保存目录不会迁移命令目录或 Chromium 网站存储，避免破坏运行环境。

- 清理所选需求：删除本机副本、预览、分析，以及由该需求各版本产生的讨论、测试任务、用例和执行记录。导入前的原始文件和飞书原文保留。
- 清理所选导出文件：删除本版本登记的 Markdown/浏览器下载文件；应用外修改过的文件会阻止删除。可以明确选择“保留文件并解除关联”，将它移出工程清理范围。
- 清理命令工作目录：删除整个工作目录和命令记录，包括手动放入的文件、测试生成文件和该目录内的依赖缓存。请先保留需要的资料。
- 清理浏览器缓存：关闭本工程网页并清理缓存，保留网站 Cookie 和登录状态。
- 删除工程：输入完整工程名称后，清除工程数据库记录、已登记导出文件、命令工作目录和历史、工程网站存储及登录状态。Chromium 占用的分区目录在退出释放后，于下次启动时删除；失败则保留清理队列继续重试。

导入、分析、对话、测试、命令审查/执行或下载尚未结束时，清理会提示先等待或停止。失败时显示错误并保留可重试的工程；已完成的文件删除不会伪装成可以回滚的事务。

旧版本没有记录导出文件所属工程，无法安全追溯这些外部文件，因此不会扫描电脑批量删除。客户端全局配置、书签、密码库、手动解除关联的文件，以及用户自己保留的旧数据库副本和系统备份，不属于单个工程删除范围。
