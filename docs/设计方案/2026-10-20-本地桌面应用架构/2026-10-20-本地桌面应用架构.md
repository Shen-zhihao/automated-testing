# 本地桌面应用架构

日期：2026-10-20（北京时间）

## 约束

- 产品只面向 Windows 和 macOS。
- 安装后以桌面应用运行，不要求用户部署服务或安装数据库。
- 不使用 Docker、Nginx、云部署脚本或联网数据库。
- 本地持久化选用 SQLite；文档、分析结果和设置已接入。
- 本地数据不自动上传。用户点击分析时才将所选文档文字发送至设置中的模型地址。

## 分层

| 层 | 职责 | 当前状态 |
| --- | --- | --- |
| React 渲染进程 | 文档库、原文、模型设置、分析展示 | 已接真实文档能力；对话和任务仍为演示 |
| Electron 主进程 | 生命周期、文件对话框、模型请求、飞书应用凭据与只读 API | 已实现；解析工作在受限内存的 Worker 中进行 |
| preload / IPC | 按业务操作暴露本机能力，校验主框架来源 | 已实现，未暴露通用文件系统、SQL 或工具执行 |
| 本地数据层 | SQLite 文档与配置仓储、版本标记 | 已实现首版；密钥经 safeStorage 加密，文档正文未加密 |
| 模型分析 | Chat Completions / Responses、分段、汇总与取消 | 已实现，按用户模型配置请求 |
| 测试执行层 | 用例调度、内置浏览器步骤执行与结果记录 | 在 Electron 主进程内运行 |

正常桌面运行从应用资源目录读取 UI，无需本地 HTTP 端口；飞书通过应用凭据直接获取访问令牌，无需浏览器登录或回调。开发时的 Vite 仅用于热更新。本地业务和执行器位于 `frontend/apps/desktop/src`，Agent、Workflow 与 Tool 通过 Mastra 在主进程内编排，React UI 通过受限 IPC 调用。

## 本地数据位置

业务数据放在 `app.getPath('userData')` 下的独立子目录，避免与 Chromium 缓存混放。安装包资源目录只读，不在源码或安装目录旁生成数据。

- `storage/test-agent.sqlite`：已实现文档、最近成功分析和配置存储。
- `reports/`：将来的截图、日志和报告。
- 迁移脚本随代码版本管理；执行时写入用户数据目录。

主进程数据模块负责写入，渲染进程只调用受限业务操作。SQLite 使用 WAL 和 user_version；遇到高于当前版本的数据库时拒绝启动，避免覆盖较新数据。后续加入任务执行时扩展迁移与备份。

SQLite 适合应用本地存储，进程直接访问本地文件，无需额外数据库服务。参考 [SQLite 官方适用场景](https://www.sqlite.org/whentouse.html)。目录约定参考 [Electron app.getPath](https://www.electronjs.org/docs/latest/api/app#appgetpathname)。

## 桌面边界

渲染进程启用 sandbox、contextIsolation，关闭 Node 集成；只加载受限的本地资源协议，禁止任意新窗口和站内跳转到外部页面。IPC 按具体能力提供窄接口，不直接暴露文件系统或进程执行对象。参考 [Electron 安全建议](https://www.electronjs.org/docs/latest/tutorial/security)。

飞书文档读取直接内置在 Electron 主进程中，以 App ID / App Secret 换取 tenant_access_token 后调用官方只读 API。应用不读取 Codex 配置、不启动外部连接器。个人或内部团队首次填写自建应用凭据并测试连接，成功后将 App Secret 经 safeStorage 加密落盘，应用访问令牌仅缓存于内存，到期合并并发请求重新获取。失败保留原配置；关闭或变更配置使旧请求失效。升级仅保留原有应用凭据，移除旧用户授权和回调配置。Windows 和 macOS 共用同一套流程，不依赖 macOS 的 shell 命令。应用需同时拥有接口权限及目标文档的阅读权限；当前读取新版文档纯文本，知识库链接先解析到文档。

打包配置只声明 macOS 和 Windows；安装包签名、公证、升级与目标机器验证在正式交付阶段实施。现有 UI 检查、macOS 启动检查和 Windows 路径测试分别报告，不将它们混称为双平台实机验证。
