# 本地桌面应用架构

日期：2026-10-20（北京时间）

## 约束

- 产品只面向 Windows 和 macOS。
- 安装后以桌面应用运行，不要求用户部署服务或安装数据库。
- 不使用 Docker、Nginx、云部署脚本或联网数据库。
- 允许本地持久化，选用 SQLite；功能按需求逐步添加，当前保留 UI 与运行骨架。
- 本地数据不自动上传。将来访问测试目标、调用模型等网络行为另行设计与配置。

## 分层

| 层 | 职责 | 当前状态 |
| --- | --- | --- |
| React 渲染进程 | 对话、技能、任务、结果展示 | 已有 UI，使用内存演示 |
| Electron 主进程 | 窗口、生命周期、本地资源、后续进程管理 | 已实现最小外壳 |
| preload / IPC | 将有限的本机能力提供给 UI，并校验参数和来源 | 按功能需要后续添加，当前未暴露系统接口 |
| 本地数据层 | SQLite 仓储、迁移、事务、备份 | 方案已确定，尚未实现 |
| Agent / 测试执行层 | 任务调度、模型、浏览器或接口执行器 | 后续添加；Python 骨架当前可选 |

正常桌面运行从应用资源目录读取 UI，不依赖本地 HTTP 端口。开发时的 Vite 仅用于热更新。现有 Python HTTP 入口只供手动开发验证；真正需要 Python 执行能力时，再收敛为主进程管理的本机子进程或受限本机接口，避免要求用户手动开启多个服务。

## 本地数据位置

业务数据放在 `app.getPath('userData')` 下的独立子目录，避免与 Chromium 缓存混放。安装包资源目录只读，不在源码或安装目录旁生成数据。

- `storage/test-agent.sqlite`：将来的业务数据库。
- `reports/`：将来的截图、日志和报告。
- 迁移脚本随代码版本管理；执行时写入用户数据目录。

主进程或单一数据模块负责写入，渲染进程只调用受限业务操作。后续加入任务执行时再确定事务、迁移和备份策略；本轮不预建业务表。

SQLite 适合应用本地存储，进程直接访问本地文件，无需额外数据库服务。参考 [SQLite 官方适用场景](https://www.sqlite.org/whentouse.html)。目录约定参考 [Electron app.getPath](https://www.electronjs.org/docs/latest/api/app#appgetpathname)。

## 桌面边界

渲染进程启用 sandbox、contextIsolation，关闭 Node 集成；只加载受限的本地资源协议，禁止任意新窗口和站内跳转到外部页面。后续添加 IPC 时按具体能力提供窄接口，不直接暴露文件系统或进程执行对象。参考 [Electron 安全建议](https://www.electronjs.org/docs/latest/tutorial/security)。

打包配置只声明 macOS 和 Windows；安装包签名、公证、升级与目标机器验证在正式交付阶段实施。现有 UI 检查、macOS 启动检查和 Windows 路径测试分别报告，不将它们混称为双平台实机验证。
