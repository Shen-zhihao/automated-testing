# 前端项目开发规则

## 1 适用范围

本规则适用于前端应用的页面与组件目录组织：

- `frontend/apps/agent-web/src`

`frontend/packages/shared-api` 属于共享 API 包，不在本规则范围；跨应用共享组件走 `frontend/packages/shared-ui`，按需抽取，不属于某个应用的 `src/components`。

## 2 核心规则

### 2.1 每个页面使用文件夹包裹

`pages/` 目录下不允许直接放置 `.tsx`、`.less` 文件，每个页面必须使用一个同名文件夹包裹。

页面入口统一使用 `index.tsx`，页面样式与入口同级，统一使用 `index.less`。

```text
src/
└── pages/
    ├── TaskList/
    │   ├── index.tsx
    │   ├── index.less
    │   └── components/
    │       └── TaskTable/
    │           ├── index.tsx
    │           └── index.less
    └── TaskDetail/
        ├── index.tsx
        ├── index.less
        └── components/
            └── LogList/
                ├── index.tsx
                └── index.less
```

路由或页面入口统一通过文件夹引用页面：

```ts
import TaskListPage from '@/pages/TaskList';
import TaskDetailPage from '@/pages/TaskDetail';
```

### 2.2 每个布局使用文件夹包裹

`layouts/` 目录下不允许直接放置 `.tsx`、`.less` 文件，每个布局必须使用一个同名文件夹包裹。

布局入口统一使用 `index.tsx`，布局样式与入口同级，统一使用 `index.less`。

```text
src/
└── layouts/
    └── MainLayout/
        ├── index.tsx
        └── index.less
```

引用布局时统一通过文件夹引用：

```ts
import MainLayout from '@/layouts/MainLayout';
```

### 2.3 全局公用组件放在 components

每个应用被多个页面或业务模块共同使用的组件，统一放在该应用的 `src/components` 目录。

全局组件同样使用文件夹包裹：

```text
src/
└── components/
    ├── StatusTag/
    │   ├── index.tsx
    │   └── index.less
    └── PageHeader/
        ├── index.tsx
        └── index.less
```

引用方式统一使用 `@/` 别名：

```ts
import StatusTag from '@/components/StatusTag';
import PageHeader from '@/components/PageHeader';
```

只在一个页面内使用的组件不应放进全局 `components`，应放入对应页面的局部 `components`。

### 2.4 页面或子页面公用组件放在局部 components

只在某个页面或页面子模块内部复用的组件，在对应的页面文件夹下新建 `components` 文件夹。

如果页面内部又拆分了子模块，子模块的公用组件放在该子模块自己的 `components` 下：

```text
src/
└── pages/
    └── DataDashboard/
        ├── index.tsx
        ├── index.less
        ├── components/
        │   └── KpiCard/
        │       ├── index.tsx
        │       └── index.less
        └── subModules/
            └── TrendPanel/
                ├── index.tsx
                ├── index.less
                └── components/
                    └── TrendChart/
                        ├── index.tsx
                        └── index.less
```

## 3 命名与引用约定

| 对象 | 目录命名 | 入口文件 | 默认导出命名 |
| --- | --- | --- | --- |
| 页面 | PascalCase | `index.tsx` | `XxxPage` |
| 布局 | PascalCase | `index.tsx` | `XxxLayout` 或 `Xxx` |
| 组件 | PascalCase | `index.tsx` | `Xxx` |

规则：

1. 页面和组件目录均使用 PascalCase；
2. 页面入口默认导出组件名以 `Page` 结尾，例如 `TaskListPage`；
3. 布局入口默认导出组件名建议以 `Layout` 结尾，或与目录名保持一致，例如 `MainLayout`；
4. 样式文件与入口文件同级，统一命名为 `index.less`；
5. 全局组件使用 `@/components/Xxx` 引用；
6. 页面内局部组件使用相对路径 `./components/Xxx` 或 `../components/Xxx` 引用。

## 4 跨应用共享组件

同一个组件在前端应用中都有使用，且出现重复实现时，应进入 `frontend/packages/shared-ui`，而不是复制到两个应用的 `src/components`。

当前只有一个应用；未来出现跨应用组件重复时，再按需抽取 `shared-ui`。

## 5 迁移说明

历史扁平页面或布局文件示例：

```text
src/pages/TaskList.tsx
src/pages/TaskList.less
src/layouts/MainLayout.tsx
src/layouts/MainLayout.less
```

属于历史实现。新增页面与布局必须按本规则创建文件夹结构；历史页面或布局迁移建议逐个提交，迁移时同步更新引用路径，避免同一目录同时存在扁平文件和文件夹结构。

## 6 检查清单

- [ ] `pages/` 下没有直接放置 `.tsx`、`.less` 文件
- [ ] `layouts/` 下没有直接放置 `.tsx`、`.less` 文件
- [ ] 每个页面都有同名 PascalCase 文件夹和 `index.tsx`
- [ ] 每个布局都有同名 PascalCase 文件夹和 `index.tsx`
- [ ] 全局复用组件位于 `src/components`
- [ ] 页面内复用组件位于页面或子模块的 `components`
- [ ] 没有把只属于单个页面的组件放到全局 `components`
- [ ] 跨应用组件进入 `shared-ui` 而不是应用内复制
