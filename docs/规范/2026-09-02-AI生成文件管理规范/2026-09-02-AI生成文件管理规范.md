# AI 生成文件管理规范

## 1 适用范围

本规范约束 AI 在项目内生成、且最终需要给人阅读的交付物，例如：

- 设计方案；
- 施工过程说明；
- 评审记录；
- 会议纪要；
- 使用说明；
- 调研报告；
- 其他 Markdown、Word、PDF 等可读文档。

代码、配置、脚本、测试输出、构建产物、日志等不属于“给人阅读的文档”，不放入 `docs/`。

## 2 核心规则

AI 生成人类可读文件时，必须同时满足以下要求：

1. 根目录为 `docs/`；
2. 按主题放入对应分类文件夹；
3. 文件名称使用 `日期-语义名称`；
4. 使用一个与文件同名的文件夹包裹该文件。

### 2.1 标准路径

```text
docs/<分类文件夹>/<YYYY-MM-DD>-<语义名称>/<YYYY-MM-DD>-<语义名称>.<扩展名>
```

### 2.2 命名要求

- 日期使用生成当天的北京时间，格式为 `YYYY-MM-DD`；
- 语义名称使用中文或英文，多个词用 `-` 连接；
- 不包含空格、`/`、`\`、`#`、`?` 等路径不安全字符；
- 文件夹名和文件名保持一致。

### 2.3 示例

```text
docs/设计方案/2026-09-02-工程架构统一版/2026-09-02-工程架构统一版.md
docs/施工过程/2026-09-02-数据中台接入过程/2026-09-02-数据中台接入过程.md
docs/会议纪要/2026-09-02-数据中台需求对齐/2026-09-02-数据中台需求对齐.md
```

## 3 分类文件夹

| 分类文件夹 | 用途 |
| --- | --- |
| `docs/设计方案/` | 架构、技术方案、模块设计 |
| `docs/施工过程/` | 开发过程、实施记录、变更过程 |
| `docs/规范/` | 项目规则、编码约定、AI 协作规范 |
| `docs/评审记录/` | 代码评审、方案评审、验收记录 |
| `docs/会议纪要/` | 会议、需求对齐、决策记录 |

没有明确分类时，应新增一个语义清晰的分类文件夹，不要把文档直接散放在 `docs/` 根目录。

## 4 附件与图片

文档引用的图片、截图、Excel、PDF 附件放在同一包裹文件夹下：

```text
docs/设计方案/2026-09-02-工程架构统一版/
├── 2026-09-02-工程架构统一版.md
└── assets/
    ├── architecture.png
    └── data-flow.png
```

## 5 特殊情况

- 同一天同一个语义名称出现多个版本时，追加 `-v2`、`-v3`，或追加时间 `-HHmmss`；
- 过程文件和最终交付物应分属不同分类文件夹，例如 `docs/施工过程/` 与 `docs/设计方案/`；
- 本规范只约束新增文件，不自动迁移历史文件。

## 6 执行要求

AI 每次生成可读交付物前，应先创建分类文件夹和同名包裹文件夹，再写入最终文件。

生成完成后，文件路径必须可以在仓库中明确引用，并遵循“一个主题一个文件夹”的原则。
