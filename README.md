# 序舟 · AI 工程工作台

> 让想法有序落地。

序舟是一款面向 Windows / macOS 的本地 AI 工程工作台，把需求资料、AI 讨论、实施拆解、测试验收和工程命令放在同一个工作空间中。

你可以从一份需求文档、一个 HTML 原型或一篇飞书文档开始，逐步梳理功能、明确实现步骤、沉淀讨论结论，再生成测试文档并执行可自动化的网页验收步骤。不同工程的资料与进度分别管理，关闭应用后仍可继续。

## 可以用序舟做什么

### 按工程组织工作

- 为不同产品、迭代或需求建立工程，集中管理相关文档、对话、测试任务和命令记录。
- 在「工程概览」查看资料、讨论和验收进展，从左侧工程列表快速切换当前工作。
- 在「文件与缓存」中按需清理资料、导出文件、命令工作目录和浏览器缓存。

### 导入资料，拆解需求

- 支持 PDF、DOCX、XLSX、PPTX、TXT、Markdown、CSV、TSV、HTML 和 JSON，也支持读取已授权的飞书文档与知识库链接。
- 导入后先预览提取内容，再按需生成「实施与验收文档」，整理功能清单、实现步骤、验收条件、实施依赖和待确认问题。
- HTML 原型可提取页面、表单约束和交互线索，帮助梳理业务流程；预览不会运行原型脚本，需要实际操作时仍应打开原文件。
- 分析结果支持 Markdown 预览、源码查看、复制和另存为 `.md`。

### 围绕需求持续讨论

- 从分析结果进入工作台，结合需求原文和已有分析，继续讨论实现思路、边界条件、缺失规则和验收方法。
- 管理、搜索和重命名工程内的对话，将有价值的回复「保留到测试任务」，避免结论只留在聊天记录里。
- 从测试任务回到讨论时，可以结合已保留结论、用例和最近执行结果继续追问。

### 设计测试，执行网页验收

- 从需求分析或讨论结论创建测试任务，补充测试范围和目标网址，生成包含前置条件、操作步骤、预期结果与风险说明的详细测试文档。
- 在客户端顶部网页标签中打开目标网站，直接登录、浏览和切换页面，无需另装自动化浏览器。
- 选择用例并生成执行计划，核对操作和断言后，再开始执行已审阅的步骤；支持点击、填写普通输入、选择、勾选及页面内容等检查。
- 查看实际执行记录和失败原因，也可导出测试文档。关闭网页标签不影响正在进行的后台测试，任务可主动停止。

生成测试文档不等于测试已通过；未执行、需要人工核验和实际失败的内容会分别记录。上传下载、验证码、支付等场景仍需人工或专用工具处理。

### 在工程中运行命令

- 在「命令执行」中打开工程工作目录，放入所需脚本和配置，运行工程相关的检查、构建或测试命令。
- 默认逐条手动确认，也可为当前工程选择「完全托管」，让后续通过范围与安全审查的命令自动执行。
- 查看命令输出、退出状态和历史记录，必要时停止运行。命令使用当前系统账号的权限，请只执行你了解的脚本；所需工具与依赖需事先在本机安装。

### 复用书签与登录资料

- 在对话输入框左下角的附件菜单中导入需求文档、浏览器书签 HTML 或密码 CSV。
- 搜索已导入的书签并在客户端网页标签中打开；密码按网站匹配，由你选择账号填入并确认登录，不自动提交表单，也不发送给模型。
- 各工程的网站登录状态与缓存独立管理；书签和加密密码库可跨工程使用。

### 保留本地资料，按习惯使用

- 文档、分析、对话、测试任务和执行记录保存在本机，重启后继续使用；API Key、飞书 App Secret 和导入密码使用系统安全存储加密。
- 在「客户端设置」中查看或更改数据保存目录，并迁移已有数据。
- 支持跟随系统、浅色和深色外观，选择后立即生效并记住偏好。

## 快速开始

### 准备环境

- 系统：Windows 或 macOS。
- 从源码启动需要 Node.js 22.16 或更高版本，以及 pnpm；项目固定使用 pnpm 9.15.9。
- 首次安装依赖需要联网。无需安装 Python、Docker 或数据库服务。
- 使用 AI 功能时，需要自行准备可用的模型服务；可连接兼容的云端服务或本机模型。

以下命令适用于 macOS 终端和 Windows PowerShell。每组命令均从项目根目录执行；如果终端已经位于 `frontend`，无需再次执行 `cd frontend`。

### 首次安装并启动

```bash
cd frontend
pnpm install --frozen-lockfile
pnpm dev:desktop
```

命令会自动打开桌面应用，并启动配套的本地界面开发服务，不需要另开终端启动后端。

### 后续开发启动

依赖安装完成后，日常修改界面、查看效果可直接运行：

```bash
cd frontend
pnpm dev:desktop
```

此模式支持界面热更新。结束开发时，在启动命令所在终端按 `Ctrl+C` 停止应用和开发服务。

### 构建并本地运行

希望体验构建后的桌面界面时，运行：

```bash
cd frontend
pnpm desktop
```

这个命令会先构建界面，再启动桌面应用，无需单独运行界面开发服务器，也不会生成安装包。

开发模式与本地运行模式分别保存数据和配置。切换模式后看到不同的工程列表属于正常现象，可在「客户端设置 → 本地数据」查看当前使用的保存目录。

### 只预览网页界面

如果只是调整页面样式，可以只运行：

```bash
cd frontend
pnpm dev
```

在浏览器中打开终端显示的地址即可。此方式仅用于界面预览，不具备桌面端的本地文档导入、安全存储、工程命令和内置浏览器等完整能力；正常使用请采用上面的桌面启动方式。

### 生成安装包（可选）

需要分发安装版时，在对应系统上执行以下命令之一：

```bash
cd frontend
pnpm package:mac
```

Windows 使用：

```bash
cd frontend
pnpm package:win
```

安装包输出到项目根目录下的 `artifacts/desktop/`，分别为 macOS 的 DMG 和 Windows 的安装程序。安装后直接打开「序舟」即可，无需每次在终端启动，也无需额外安装 Node.js、pnpm 或数据库服务。模型服务和工程命令所需的外部工具仍需自行准备。

## 第一次打开后怎么用

### 1. 配置模型

打开左侧「客户端设置 → 大模型」，填写服务地址（Base URL）、模型名称和 API Key，选择服务支持的接口格式，再点击「保存并测试连接」。本机免鉴权模型可不填 API Key。

服务地址应填写接口根地址，而不是完整的请求地址。连接测试只发送一条简短消息，不发送需求文档。详细参数说明见[文档分析与模型设置](docs/使用说明/2026-10-20-文档分析与模型设置/2026-10-20-文档分析与模型设置.md)。

### 2. 新建工程并导入需求

点击左侧「新建工程」，填写工程名称和可选说明，然后进入该工程的「需求分析」导入本地文件。也可以从对话输入框的附件菜单导入。

如需读取飞书文档，先在「客户端设置 → 飞书应用」填写自建应用的 App ID 和 App Secret，测试连接成功后再导入链接。应用还需要获得目标文档或知识库的阅读权限；连接成功不代表所有文档都可读取。

### 3. 生成实施与验收文档

先检查「提取原文」是否完整，再按需填写补充要求，点击「生成实施与验收文档」。查看功能拆解和验收标准，对不明确的规则继续补充说明。

导入文件不会自动分析，也不会自动把文档发送给模型。由你点击分析，或主动发起相关讨论、测试文档及执行计划生成时，才会将相应材料提交给配置的模型服务。

### 4. 讨论方案，沉淀结论

在分析结果中点击「在工作台讨论」，围绕某个功能或整份需求继续提问。将确定的回复保留到测试任务，作为后续测试设计的依据。

### 5. 生成测试文档并按需执行

进入「测试验收」，完善任务范围和目标网址，生成详细测试文档。如果要执行网页测试，先打开测试网页并完成登录，再选择用例、生成计划，审阅后开始执行。在执行记录中核对实际结果，最后按需导出 Markdown。

工程需要运行本地检查或测试脚本时，再进入「命令执行」，准备工作目录并确认相应命令。

## 使用时需要了解

- **不是所有功能都需要联网。** 查看已有资料、管理工程和阅读历史结果在本机完成；调用远程模型、读取飞书或访问目标网站时需要相应网络连接。
- **文档预览不等于完整还原原文件。** 扫描 PDF、图片文字、附件等内容不会自动识别；导入时请查看提示，必要时补充文字资料。旧版 DOC / XLS / PPT 请先转为新格式。
- **生成内容需要核对。** AI 的实施建议和测试设计不能代替人工确认，执行记录只代表本次实际完成的检查。
- **清理前确认范围。** 删除应用内文档不会删除原始文件或飞书文档；清理命令工作目录会删除其中放入的文件，请先保存需要保留的内容。密码 CSV 含明文敏感信息，导入后请妥善保管。
- **macOS 关闭窗口不一定退出应用。** 需要完全退出时使用菜单「退出」或 `Cmd+Q`；开发运行也可在终端按 `Ctrl+C`。
